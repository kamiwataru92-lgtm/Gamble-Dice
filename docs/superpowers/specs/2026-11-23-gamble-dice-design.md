# Gamble Dice 設計書

日付: 2026-11-23

## 1. 目的と背景

友達同士がそれぞれ自分の端末（スマホ・PC）から参加して遊ぶ、オンラインのダイスゲーム。
「どこまで攻めるか」を自分で決めるリスク選択と、没収されたクレジットが中央に貯まっていく総取りの駆け引きが核。

ログイン式にして、ゲーム内通貨（コイン）をアカウントに保存する。**将来ほかのゲームを作ったときにも同じコインを共有できる**ことが目的の一つ。

## 2. ゴール / 非ゴール / アンチゴール

**ゴール**
- 各自の端末から部屋コードで同じ部屋に参加し、リアルタイムに遊べる
- Google ログインでアカウントごとにコインが保存され、別のゲームからも同じウォレットを読み書きできる構造
- 課金なし（Firebase の無料 Spark プランの範囲で動く）
- 没収ルールを部屋ごとに切り替えて試せる（後でどちらかに決める）

**非ゴール**
- 本格的なチート対策（友達同士で遊ぶ前提。ダイス判定は端末側で行う）
- 実際のお金との交換・課金
- 見知らぬ人とのマッチング

**アンチゴール（動いても失敗とみなすもの）**
- Blaze プラン（従量課金・カード登録）が必要になる構成
- ゲームの途中で通信が切れた人のコインが消える／二重に増える

## 3. 制約

- Firebase Spark プラン：Authentication、Cloud Firestore、Hosting のみ使用。Cloud Functions は使わない
- サーバーは持たない
- ゲームロジックはクライアント（ブラウザ）で実行し、Firestore のトランザクションで整合性を保つ

## 4. 検討した作り方（Approaches）

| 案 | 内容 | 判断 |
|---|---|---|
| 自前サーバー（Node.js + Socket.IO） | サーバーがダイスと状態を管理。ズル不可 | **不採用**：サーバーを持ちたくない |
| ホストのブラウザが親（WebRTC / PeerJS） | サーバー不要。ホストが閉じると終了、つながらない回線あり | **不採用**：ログインとゲーム間の通貨共有ができない |
| Firebase + Cloud Functions（Blaze） | 判定をサーバー側で行うのでズル不可 | **不採用**：カード登録・従量課金をしたくない |
| **Firebase（Spark）+ クライアント判定** | ログイン・通貨保存・リアルタイム同期を無料で実現。ズルは防げない | **採用**：友達同士で遊ぶ前提なので許容 |

## 5. ゲームルール

### 5.1 通貨とクレジット
- **コイン**：アカウントに保存されるゲーム内通貨。初回ログイン時に **1000 コイン**を配布（※提案値）
- **クレジット**：1ゲームの中だけで使う点数。**1 コイン = 1 クレジット**（※提案値）
- 参加時に、持ち込むクレジット額（**1〜100**、インフレ防止）を決めてコインから換える。**途中で追加の換金は不可**。ゲーム中に 100 を超えるのは可
- ゲーム終了時、手元のクレジットはコインに戻る

### 5.2 部屋
- ホストが部屋を作り、6文字の部屋コードを共有。**2〜6人**（※提案値）
- ホストは部屋を作るときに次を設定する
  - **没収ルール**：「賭けた額だけ没収」または「持っているクレジットの半分を没収」
  - **連続当たりの必要回数**：初期値 3（※提案値）
- ホストが開始すると、**順番をランダムに決める**
- 開始後の途中参加は不可（※提案）。状態は Firestore にあるので、ホストが抜けてもゲームは続く

### 5.3 手番の流れ
1. 自分の番が来たら「振る」か「パス」を選ぶ
2. 振る場合、**賭け額**（1以上、手持ちクレジット以下）と、**ハズレの確率**（1/6〜5/6）を選ぶ
3. ダイスを振る
   - **当たり**：賭け額 × 増加率 のクレジットが増える。連続当たり数 +1。続けて「もう1回振る」か「パス」を選べる
   - **ハズレ**：没収ルールに従ってクレジットを没収し、**中央のプール**に入れる。手番終了。連続当たり数リセット
4. パスすると手番終了。連続当たり数リセット

**ハズレ確率ごとの増加率**（※提案値。設定ファイルで変更可能にする）

| ハズレ確率 | 1/6 | 2/6 | 3/6 | 4/6 | 5/6 |
|---|---|---|---|---|---|
| 当たり時の増加 | +10% | +20% | +40% | +60% | +90% |

ダイス表現：6面のうちハズレの面数が 1〜5 面。出目がハズレの面なら負け。

### 5.4 没収ルール（部屋ごとに選択）
- **賭けた額だけ**：賭け額を没収
- **半分**：その時点の手持ちクレジットの半分（切り捨て、最低1）を没収
- いずれも没収額はプールに入り、**プレイヤーごとの没収累計**を記録する

### 5.5 失格
- クレジットが 0 になったら失格。以降は観戦のみ

### 5.6 ゲーム終了
- **連続当たり達成**：1人が1回の手番の中で必要回数連続で当たったら、その人がプールを**総取り**して即終了
- **全員パス**：失格していない全員が、2周続けて「一度も振らずにパス」したら強制終了（誰かが振った時点でカウントはリセット）。プールは**各プレイヤーの没収累計の割合で山分け**（失格者も含む）
- **全員失格**：全員パスと同じ扱いで山分け
- 終了時、各プレイヤーのクレジットをコインに戻す

## 6. 技術構成

- **フロントエンド**：Vite + TypeScript + React（※実装側の判断）
- **Firebase**：Authentication（Google ログイン）、Cloud Firestore（リアルタイム同期）、Hosting（公開）
- **テスト**：ゲームルールは純粋な関数として切り出し、Vitest で単体テスト

### 6.1 データ構造（Firestore）

```
users/{uid}
  displayName, coins, createdAt

rooms/{roomCode}
  hostUid, status: "waiting" | "playing" | "finished"
  settings: { forfeitMode: "bet" | "half", streakToWin: number }
  turnOrder: [uid...], currentTurnIndex, currentStreak
  consecutivePasses, pool
  lastRoll: { uid, bet, loseFaces, face, win, delta }
  result: { reason: "streak" | "allPass", payouts: {uid: credits} }

rooms/{roomCode}/players/{uid}
  displayName, credits, buyIn, forfeitedTotal, eliminated, settled
```

- **ウォレットは `users/{uid}.coins` に置き、ゲームに依存させない**。将来のゲームも同じフィールドを使う
- 状態の更新はすべて Firestore トランザクションで行う（手番の人のクライアントが自分の行動を書き込む）
- 換金（コイン→クレジット）と精算（クレジット→コイン）もトランザクション。`settled` フラグで二重精算を防ぐ
- 終了時に接続していなかった人は、次にログインしたときに未精算の部屋を精算する

### 6.2 セキュリティルール（最低限）
- `users/{uid}` は本人のみ読み書き可
- 部屋とプレイヤー情報は参加者のみ読める。行動の書き込みは参加者のみ
- 判定そのものの正しさまでは保証しない（非ゴール）

## 7. 実装側に任せること

- 画面デザイン、ダイスのアニメーション
- 手番の時間切れ（※提案：60秒操作がなければ自動でパス。切断した人で止まらないようにするため）
- 山分けの端数処理（※提案：切り捨てて、余りは没収累計が最も多い人へ）
- 部屋コードの生成方法

## 8. 利用者側で必要な作業

- Firebase プロジェクトの作成（無料）と、Google ログインの有効化
- Firebase の設定値（apiKey など）を渡す
- 公開時の `firebase deploy`（手順は README に記載する）

## 変更履歴

### 2026-11-23：ゲームごとのランダム確率・期待値 110%・部屋の継続
- ハズレ確率はプレイヤーが選ぶのではなく、ゲーム開始時に 2/6・3/6・4/6 からランダムに決まり、そのゲーム中は全員共通
- 当たりの増加率は期待値 110% になるよう 2/6 → +65%、3/6 → +120%、4/6 → +230%
- 賭け額は最低 20。持ち込みは 20〜100。クレジットが 20 未満になったら失格（残りは終了時にコインへ）
- 没収ルール「半分」は削除（賭けた額のみ）
- 部屋はゲーム終了後も残り、「次のゲームへ」で同じ部屋の次のゲームを始める。持ち込みは毎回やり直し、前のゲームの残りはコインに戻す。ゲームの合間なら抜ける・入るが自由
- ホストの役割はなくし、参加している人なら誰でも開始できる

### 2026-11-23：コインの増えすぎ対策
- 1 回の賭け額は最大 100（勝った分を全額賭け直して倍々に増やせないように）
- 期待値を約 105% に下げる：2/6 → +58%、3/6 → +110%、4/6 → +215%（プラスは保つ）
- 失格していない人が 1 人になったら強制終了。プールは没収額の割合で山分け（残った 1 人が振り続けて増やすのを防ぐ）

### 2026-11-23：期待値をプール込みで 105% に
- ハズレた賭け額は消えずにプール経由で誰かに戻るため、全員合計の期待値は 100% +（当たる確率 × 増加率）
- 以前の +58% / +110% / +215% では全員合計が約 139% / 155% / 172% になっていた
- 増加率を 2/6 → +7%、3/6 → +10%、4/6 → +15% に変更（全員合計で約 105%）。プールの総取りが主役のバランス

### 2026-11-23：失格者は全て失う
- クレジットが 20 未満で失格した時点で、残りのクレジットもプールに没収
- 「全員 2 周パス」「残り 1 人」で終わったときは、生き残っている人に自分が没収された分だけが戻る。失格した人には戻らず、その分は消える
- 連続当たりの総取りは従来どおり、勝った人がプールを全部もらう

### 2026-11-23：期待値をプール込みで 150% に
- 105% では増え方が小さすぎて面白くないため、全員合計（プール込み）で 150% に
- 2/6 → +75%、3/6 → +100%、4/6 → +150%

### 2026-11-23：期待値をプール込みで 200% に
- 2/6 → +150%、3/6 → +200%、4/6 → +300%

### 2026-11-23：連続当たり・連続ハズレを部屋全体で数える
- 連続当たり：誰が振っても数え、設定回数目（初期値 3）を当てた人がプールを総取り。ハズレで数え直し、パスでは数え直さない
- 連続ハズレ：誰が振っても数え、3 回続いたらプールが全部消える（ゲームは続く）。当たりで数え直し、パスでは数え直さない
- プールが消えたら、各自の「没収された分」も 0 に数え直す（「2 周パス」「残り 1 人」で戻る分がなくなる）
